## shop-scout (prikotov, PHP)

`triage: step 3 · close 0.75 · verdict: → Inspect → брать эвристики мусорных отзывов`

### Мусорные отзывы

`lib/Analysis/ReviewFilter.php` `isJunk()`, L59-116. Отзыв считается мусором, если сработало любое из правил:

1. Текст, плюсы и минусы пусты (L66).
2. «Ещё не пользовался» (L24-32): `ещ[ёе]\s+не\s+(польз|тестир|провер|распак|вставил|подключ|установил)`, `пока\s+не\s+(польз|тестир|провер|распаков)`, `не\s+успел\s+(провер|польз|тестир)`, `дополн(ю|ью позже|ию)`, «5 звёзд авансом», «за будущую покупку».
3. Чистая логистика (L83-94). Есть слово из `LOGISTIC_WORDS` (курьер, доставк, упаковк, постамат, пвз, выдач, забрал, приехал/пришла быстро). Нет слов о самом товаре (сломал|не работает|работает|качеств|брак|звук|шум|удобн|мощност|греется|месяц|недел|год…). Короче 120 символов.
4. Мало информации (L97-107). Не длиннее 25 символов и начинается с `LOW_INFO` (норм, ок, хорошо, отлично, супер, класс, топ, спасибо, доволен, советую, рекомендую, пойдет…). Либо 3 слова или меньше без цифр и запятых.
5. «Поставил N звёзд» короче 80 символов (L111).

### Брак, подделка, выбор

- **Регэксп брака** (`Analyzer.php` L218): `брак|сломал|не\s+работает|вышел\s+из\s+строя|разболтал|рассыпался|дефект|некачественн|палён|подделка|не\s+оригинал`. Каждое совпадение даёт флаг «жалобы на брак: N».
- **Подозрение на подделку** (L186-241):
  - цена ниже 0.70 медианы по всей выдаче;
  - рейтинг ниже 3.8;
  - меньше 5 отзывов — низкая уверенность.
- **«Рекомендую»** (L88-130): `0.35·rating + 0.25·log-отзывов + 0.25·priceScore + 0.15·brand − 0.3·defects − 0.5·wrongBrand`. priceScore от отношения цены к медиане: < 0.7 → 0.3, ≤ 1.1 → 1.0, дальше убывает. «Дешевле-оригинал» — минимальная цена среди не-подделок с совпавшим брендом.
- Матчинг бренда по латинскому токену из запроса не брать: наши тиры брендов лучше.

## ozon-shopping-mcp (neosheps, TS)

`triage: step 3 · close 0.72 · verdict: → Inspect → брать схему сессии`

- **Разовый setup** (`browser-session.ts` L48-105). Открывается видимый системный Chrome (`channel: chrome`, `--disable-blink-features=AutomationControlled`). Каждые 1.5 с идёт проверочный запрос, пока не придёт 200 (до 120 с). Пользователь сам проходит проверку. Затем `storageState()` и UA сохраняются в `~/.config/ozon-shopping-mcp/session.json`.
- **Headless-запуск** (L203-242). Headless-браузер поднимается с сохранёнными `storageState` и UA. Ответ не 200 или 401/403/307 даёт явный `SESSION_EXPIRED`: «перезапусти setup». Без stealth-плагинов, CDP и постоянного профиля.
- **Эндпоинт.** `https://www.ozon.ru/api/composer-api.bx/page/json/v2?url=<path>`, вызывается через `fetch()` внутри `page.evaluate` с куками и TLS страницы. Пути: `/search/?text=…`, `/product/<id>/`, `/product/<id>/reviews/`.
- **Отзывы** (`parsers.ts` L273-306), виджет `webListReviews`. Поля: `content.positive/negative` (плюсы и минусы), `usefulness.useful`, **`isItemPurchased`**, `content.photos`, `publishedAt`.
- **Нагрузка.** Последовательная очередь, ≥750 мс между запросами, браузер закрывается после 5 мин простоя, таймаут 30 с.

## ru-marketplace-mcp (Vladimir-Human)

`triage: step 3 · close 0.70 · verdict: → Inspect → CDP-ступень держать в запасе`

- **Причина** (`docs/ANTI_BOT.md`): `composer-api.bx` отвечает датацентровым IP бесконечным 307 `__rr=N`, TLS-имперсонация не помогает.
- **Две ступени.** Сначала `curl_cffi` с паузами (с домашнего IP обычно работает). Если не прошло — fetch через **собственный Chrome по CDP** (`mcp-core/.../chrome_cdp.py`): `--remote-debugging-port=9222` на 127.0.0.1, отдельный профиль, окно видимое (headless детектится), `connect_over_cdp`, вкладка на каждый запрос. Пользователь логинится в этом профиле один раз руками.
- **Детект блокировки.** Статусы `{401,403,407,429,500,502,503,504}` дают `NavBlocked` (Playwright `goto` на них не падает), плюс таймаут вкладки 25 с. Если нет `widgetStates`, бросается `ParserDriftError`, а не возвращается пустой результат.
- **Challenge handoff** (`CDP_SETUP.md`). Вкладка с проверкой остаётся открытой, окно показывается, пользователь решает проверку, повторный вызов читает ту же вкладку. Для Ozon не используется.
- **Правила `ADDING_A_SOURCE`**:
  - отсутствующее значение — `None`, не 0;
  - предупреждения идут в `meta.warnings` и `healthy:false`;
  - у каждого источника есть `<name>_selfcheck`;
  - не делать инструмент под возможность, которой нет у площадки.

## Сравнение с buy-smarter

Что уже есть:
- `ranking/review_trust.py`: доля пятёрок > 95%, кластеризация дат, короткие тексты. Подключено через `services/recommend.py:1437 _apply_review_trust`. Агент-разведчик ошибочно счёл его неподключённым, перепроверено grep.
- `_is_suspicious_price` (`engine.py` L384): цена < 0.4 доверенной медианы, только для noname.
- Ozon: `MS ozon/playwright_session.py` перезапускается на 403/307, есть ретраи, idle и лок. Антибот-регэксп по title (`browser.py` L32).

Чего нет:
- Текстового фильтра мусорных отзывов.
- Полей отзыва: `MS ozon/parse.py _review_text` (L222) склеивает плюсы, минусы и комментарий в одну строку и выбрасывает `useful`, `isItemPurchased` и фото. В `RawReview` (`base.py` L53) таких полей нет.
- Сохранения сессии Ozon (`storage_state`) и явного «сессия истекла».
- Классификации статусов в духе `NavBlocked` кроме регэкспа по title.

## Что портировать (по ценности и затратам)

1. **Фильтр мусорных отзывов** как чистая функция `filter_junk(reviews)` в `ranking/review_trust.py`. Доля мусора становится ещё одним сигналом доверия, а в `llm/review_summary.py` уходят только содержательные тексты.
2. **Расширить `RawReview`** полями `pros`, `cons`, `useful`, `purchased`, `has_photos`. Заполнять их в `ozon/parse.py` и `kaspi/parse.py` (у Kaspi есть `comment.plus/minus`). Низкая доля `isItemPurchased` — сигнал накрутки, отзывы с фото — плюс к доверию.
3. **Регэксп брака** по минусам и тексту: штраф и строка «жалобы на брак: N» в отчёте. Дёшево и без LLM.
4. **`storage_state` для Ozon.** Команда `setup` открывает видимый браузер до ответа 200 и сохраняет состояние, headless-запуски его загружают. При 401/403/307 после ретраев выводить явное «сессия истекла».
5. Обсудить: рейтинг < 3.8 как штраф, порог подозрительной цены 0.7 медианы против наших 0.4 только для noname.
6. Запасной вариант: CDP-ступень (~1k строк у них). Только если headless с `storage_state` будут продолжать блокировать.
