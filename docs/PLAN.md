# Планы

Все планы проекта живут здесь, в одном файле. Новый план — раздел в «В работе» (формат: `docs/playbook.md`,
«Формат плана»). Большая задача может жить в своём файле `docs/tasks/<дата>-<тема>.md`, но пункт со ссылкой на него
всегда здесь. Когда план готов, он сжимается до строки в «Сделано», а полный текст остаётся в git.
Старые планы из папки `docs/plans/` читаются так: `git show eb26d5e:docs/plans/<файл>.md`.

## Открытое: баги, фичи, идеи (индекс, 2026-11-05)

Что здесь уже есть: планы и фичи в «Открыто», риски в «System design». Ниже только то, что выше названо числом, а не строками.

### Баги

- ✅ 2026-11-05 Таймаут джобы по умолчанию 300 с → 600 с (`config.py`, `docker-compose.yml`), долгие запуски (323 с) больше не падают как `timeout`; не закоммичено. [system-design.md, Risks](system-design.md) (`docker-compose.yml:7`, `worker.py:167-208`).
- Kaspi с IP датацентра отдаёт 429, без `KASPI_PROXY` API-режим чаще даёт `no_match`/`failed`. [Risks](system-design.md) (`services/collect.py:67`).
- Лимит 10 джобов/600 с на клиента равен мощности воркера, очередь без ограничения глубины. [Risks](system-design.md) (`jobs.py:324`).
- Лучший пропускает карточку с ценой 0 (#27), две ошибки округления у «выгодного» (#29). [roles-lean-findings](tasks/2026-11-02-roles-lean-findings.md).
- 2026-11-05 CO2 и CO путаются: запрос «датчик CO2 углекислого газа для квартиры, с Wi-Fi, до 40000 тг, Алматы» дал лучшим «Сигнализатор угарного газа/датчик GN-CO2» (Ozon, 7 585 ₸, 47/100). Категория «датчик CO2» без BrandBook, фильтр «Wi-Fi» его не отсеял. Нужен отсев по смыслу категории (CO2 ≠ CO), не по подстроке `CO2` в названии.
- 2026-11-05 Kaspi пуст при живой карточке: запрос «PTH-9CW датчик CO2 Tuya, Алматы» вернул 5 предложений, все Ozon, хотя на Kaspi есть [MOES PTH-9CW](https://kaspi.kz/shop/p/mnogofunktsional-nyi-datchik-moes-pth-9cw-ekosistema-tuya-smart-google-home-smart-life-home-assistant-161099804/). Запуск с десктопа в Алматы; в отчёте про Kaspi ни ошибки, ни 429 — причина не выяснена (поиск по модели? молчаливый сбой?).

### Планы и фичи

- Восстановление мёртвого воркера занимает 2 x таймаут (1200 с), клиент не видит смены статуса. [Risks](system-design.md) (`worker.py:53`).
- Автомат отказа (circuit breaker) для медленного маркетплейса: Kaspi ждут целиком, до 63 с на стадию. [Risks](system-design.md) (`services/collect.py:738`).
- Политика хранения `price_snapshots` (строки отфильтрованных карточек копятся). [Risks](system-design.md), шаг 20 [logic-map.ru.md](logic-map.ru.md).
- Бэкап и проверка восстановления `category_knowledge` и образцов стиля в локальном режиме. [Risks](system-design.md).
