# Задача: характеристики объявлений OLX, которых нет в объявлении

Статус: не начата, ждёт решений по вопросам ниже. Пункт в `docs/PLAN.md`, раздел «Открыто».

## Проблема

У объявления OLX обычно есть только название, описание, цена, город и фото. Структурированных характеристик нет.
Поэтому жёсткое требование запроса для OLX проверить нельзя. Пример 2026-10-31: «посудомоечная машина высотой до
50 см, бюджет 90 000». После 7412291 раздел OLX показывает три самых дешёвых подходящих объявления, но высоту ни
у одного не проверяет. «Посудомоечная машина 60см» (полноразмерная) прошла бы наравне с настольной.

## Что уже есть в коде

- Текст объявления: `services/matching.ad_text` (название + описание продавца), сейчас по нему ищутся только дефекты.
- Модель из названия: `ModelBook.resolve` и `llm/canonicalize` (Jev, затем LLM), только по названию.
- Фото: `RawProduct.image_urls` (все фото объявления, `market_sources/olx/parse._images`).
- Обработка изображений: модуль `style` (ONNX-модель на CPU, extra `style`, кэш векторов `style_vectors`).
  Она про вкус одежды, характеристики по фото не определяет.
- Характеристики Kaspi: `source.specs(product_id)`, их проверяют обязательные свойства у новых товаров.

## Подход: лестница источников, от дешёвого к дорогому

Каждая ступень запускается, только если предыдущая не дала ответа, и только для объявлений, которые иначе попали бы
в отчёт (топ после релевантности и бюджета).

1. **Текст объявления.** Регулярки по названию и описанию: размеры («45 см», «высота 44»), «настольная»,
   «компактная», «встраиваемая». Без сети и LLM.
2. **Модель → карточка магазина.** Модель из названия или описания (`ModelBook`, `canonicalize`, описание тоже).
   По модели ищем карточку на Kaspi или Ozon и берём её характеристики, а если повезёт, то и отзывы (средняя
   оценка, сводка). Кэш по модели в хранилище, чтобы не искать одну модель дважды.
3. **Фото.** Только если ступени 1–2 не помогли и требование касается того, что видно на фото (высота, форма,
   цвет). (а) Модель или наклейка на фото: OCR или VLM. (б) Форма: полноразмерная или настольная видна на фото.
4. **Не определено.** Объявление помечается «высота не проверена» и показывается или скрывается по опции ниже.

## Опция: неопределённые объявления

Показывать ли объявления OLX, у которых требование не проверено. По умолчанию показывать с пометкой «не
проверено: высота». Опция в настройках поиска и флаг CLI (правило CLI = GUI), например `--olx-unverified hide`.

## Открытые вопросы (с рекомендацией)

1. **Где обрабатывать фото?** Рекомендую VLM через claude-cli (OmniRoute) с маленьким превью только для 1–3 фото
   топ-объявлений, и только на ступени 3. Локальная модель для одной задачи «форма товара» не окупится. OCR —
   только если VLM дорог.
2. **Всегда ли нужно?** Нет. Только когда у запроса есть жёсткое требование (обязательное свойство или `dims`),
   которое у объявления не проверено, и объявление попадает в отчёт. Без LLM (`--no-llm`) работают ступени 1–2.
3. **Лимит стоимости.** Не больше N вызовов VLM на поиск (например 5). Ответы кэшировать по URL фото.
4. **Отзывы с карточки магазина.** Показывать в строке OLX как «отзывы о модели (Kaspi): 4.7, 120». Рекомендую
   во второй итерации, после характеристик.
5. **Неопределённые по умолчанию.** Рекомендую показывать с пометкой: пустой раздел OLX хуже, чем объявление
   с явным «не проверено».

## Готово, когда

- «посудомоечная машина высотой до 50 см» до 90 000: настольная из OLX показана как подходящая, «60 см» скрыта
  или помечена; живой прогон записан сюда.
- Тесты на каждую ступень; карта логики EN и RU (шаг 21) и CHANGELOG в том же коммите.
