# План: «одежда под мой вкус» — первая версия (возможность `style`)

Даниил хочет искать одежду под свой вкус: качественно, быстро, умеренно просто, отдельным необязательным модулем.
Разведка — `docs/analogs/fashion-taste.md`, исследование и его проверка — `docs/research/2026-10-27-clothing-taste*.md`,
спайк — `docs/spikes/clothing-taste-spike.md`. Что показал спайк:

- `Marqo/marqo-fashionSigLIP` в готовом ONNX int8 (зрение 90 МБ, текст 111 МБ) на CPU — 82 мс на фото пачкой, без torch;
  отложенный лайк обходит 87–97 % карточек Kaspi той же категории, контроль — на уровне случайности.
- **Узкое место — выборка**: общий запрос даёт дешёвые безымянные карточки, и ни верх, ни низ ранжирования не «ваши».
  Карточки любимых брендов в той же выборке сами поднимаются наверх (топ-16 кроссовок — 100 % брендов).
- **«Категорически нет» словами** («cheap glossy white plastic sole») находит именно такие карточки без единого фото;
  фото-дизлайки точнее.
- Бренды из `tiktok-lazy-follower/digests/menswear-actions.md` на Kaspi есть (Samba, Brooks, Helly Hansen, Salomon…),
  у части цена говорит «реплика» — проверка подделок здесь к месту.

Профиль стиля — три части: **бренды** (что искать), **образцы** (фото и лайки — как ранжировать), **«нет»** (фразы и
фото-дизлайки — что опускать). Встраивается как возможность (ADR-0005): `searches` — поиски Kaspi по брендам,
`enrich` — векторы фото, `axis` — ось «Стиль», `notes` — «похоже на ваше фото X».

## Решения

| # | Вопрос | Рекомендация | Почему |
|---|---|---|---|
| В1 | Модель и рантайм | `Marqo/marqo-fashionSigLIP`, `onnx/vision_model_int8.onnx` + `onnx/text_model_int8.onnx` + `tokenizer.json`, через `onnxruntime` и `tokenizers`; extra `buysmarter[style]`; веса скачиваются при первом включении в кэш (`platformdirs`), с проверкой SHA-256 | Спайк: готовые файлы, без torch и своего экспорта; int8 ≈ fp32 (косинус 0.988) |
| В2 | Когда возможность включена | Категорийная: Jev при первой встрече типа товара отвечает «одежда/обувь/аксессуары, где важен вид?» (как остальные возможности); работает, только если профиль стиля не пуст и extra установлен, иначе — строка в «Как оценивали», почему нет | Не-одежда не платит ничего; переключатель на отчёте и `category set` — как у прочих |
| В3 | Один профиль или по категориям | **Один профиль** на пользователя; оценка — максимум сходства по всем образцам | Спайк: образцы другой категории дают ≈ 0.5, максимум сам выбирает свою категорию; разметка не нужна |
| В4 | Фото карточки | Главное фото (`image_url`), одно на товар; `Candidate.image_url` из `RawProduct`; загрузка параллельно (8), вектор в кэше SQLite по URL (BLOB float32), numpy для скоринга; без фото — оси нет, строка «нет фото» | 100 новых ≈ 8 с, повторно — мгновенно; sqlite-vec не нужен при сотнях векторов |
| В5 | Ось «Стиль» | Вес 20 из 100; балл — сходство с ближайшим образцом, нормированное по выборке (0–20); «нет»: штраф за близость к фото-дизлайку выше порога и 0.15 за каждую z-единицу фразы «нет» выше нуля; объяснение — «похоже на ваше фото «…» (0.86)», «похоже на «нет: …»» | Числа и формулы — из спайка; объяснение — правило проекта «каждый балл объяснён» |
| В6 | Бренды → поиск | Список брендов в профиле; `searches` даёт до 6 поисков Kaspi «<тип товара> <бренд>» с бренд-словом как обязательным в названии; бренды в порядке списка | Существующий механизм доп. поисков; без брендов выборка «не ваша» (спайк) |
| В7 | Фразы на русском | Фразы «нравится» и «нет» хранятся как написаны; при сохранении один вызов LLM переводит в 2–3 англ. описания товара (текстовая башня англоязычная); без LLM — фраза должна быть по-английски, иначе предупреждение | Токенизатор SigLIP v1 англоязычный; «без X» не писать — модель не видит отрицание |
| В8 | Лайки и дизлайки | В отчёте GUI — 👍/👎 в строке товара; CLI — `buysmarter style like/dislike <ссылка на товар>`; пишется вектор главного фото как образец | Паритет CLI = GUI; ссылка есть в обоих отчётах |
| В9 | Управление профилем | GUI: экран «Стиль» в боковой панели (фото-образцы сеткой с добавлением и удалением, бренды, фразы «нравится»/«нет»); CLI: `buysmarter style show / add <файлы или папки> [--no] / remove / brands / like-text / never / download`; на экране — кнопки «Добавить папку…» и «Скачать модель» (просьба пользователя: всё управление модулем в одном разделе) | Одна группа CLI, как `prefs` и `category` |
| В10 | Свои фото | Копия в `~/.local/share/buysmarter/style/`, EXIF стирается при копировании; наружу не уходят никогда (LLM получает только текст фраз) | Приватность; профиль не ломается, если исходники переместят |
| В11 | MCP, HTTP API, сервер | Не меняются: возможность есть только у локального профиля; сервер — выключена | Многопользовательский профиль стиля — отдельная задача |
| В12 | Отложено | Попарная модель Bradley–Terry (когда будет ≥ 15 пар), LinUCB/MMR, `style eval`, MODA, подсказка брендов по фото через VLM, импорт из дайджеста, несколько ракурсов, обрезка фона, бирки | Сначала польза базовой версии |

## Порядок работы

Тест первым, коммит на шаг, сразу в main и push; карта EN + RU в том же коммите, где меняется поведение; CHANGELOG в
`[Unreleased]`. Затронутые тесты на шаге, полный прогон в конце (`QT_QPA_PLATFORM=offscreen uv run pytest -q`, ruff,
`ruff format --check`, `mypy src`). GUI — скриншоты обеих тем после каждой правки, в т. ч. 960×640, чек-лист
`~/dev/docs/GUI/qt-desktop-guide.md`. Тесты не скачивают модель: кодировщик подменяется векторами.

## Готово, когда

- [ ] С профилем стиля «мужские кроссовки» показывает наверху вещи любимых брендов и стиля, а «белую пластиковую
      подошву» — внизу; у каждой строки объяснение оси «Стиль».
- [ ] Без extra или без профиля поиск не меняется, причина видна в «Как оценивали».
- [ ] CLI и GUI умеют одно и то же (профиль, лайки, переключатель).
- [ ] Полный прогон зелёный; ruff, format, mypy чистые; документы обновлены; живой прогон записан.
