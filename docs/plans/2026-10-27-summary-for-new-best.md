# План: новый лучший после штрафов по отзывам получает свою сводку (находка #14)

Находка #14 (`docs/plans/2026-10-22-logic-map-fixes.md`): сводки отзывов строятся по топ-3 до штрафов. Если сводка
выявила подделку или серьёзные проблемы и лучший опустился, лучшим может стать №4 — без сводки, без проверки Jev на
подделку и без вердиктов по обязательным свойствам. Отчёт говорит «лучший выбор не вошёл в топ-3, чьи отзывы
сводятся». Где в коде: `services/review_pass.review_pass` (`_summarize_top`, `_apply_summary_penalties`,
`_apply_requirement_checks`). Общий код для CLI, GUI, MCP и API — входы не меняются.

## Решения

| # | Вопрос | Рекомендация | Почему |
|---|---|---|---|
| В1 | Как чинить | После штрафов, пока у лучшего нет итога сводки: свести его отзывы, применить штраф и вердикты **только этой** сводки, пересобрать; повторять | Как в находке. Повторное применение старых сводок штрафовало бы дважды |
| В2 | Сколько раундов | Не больше 3 добавочных сводок (`_REVIEW_SUMMARY_TOP_N`); исчерпали — строка «лучший выбор не вошёл в 6 кандидатов, чьи отзывы сводятся» (было «в топ-3») | Каждая — вызов LLM и, вне топ-6 Kaspi, загрузка отзывов; обычно 0–1 |
| В3 | Сводки нет (мало отзывов, сбой LLM) | Это итог: не повторять, в отчёте — его причина, как у топ-3 | Повтор не даст другого исхода |
| В4 | Без LLM или без сводок | Как сейчас | Сводок нет, лучший не меняется штрафами сводок |
| В5 | Отчёт | Новой строки нет: у нового лучшего просто есть сводка | — |
