# План: #26 — сначала обучение новой категории, потом поиск

Находка #26 (`docs/plans/2026-10-22-logic-map-fixes.md:39`): поиск по новой категории идёт до обучения, первый
результат без брендов и состава. Решение Даниила 2026-10-24: GUI и CLI сначала ждут обучения, потом ищут с книгами;
MCP и HTTP API не меняются (у клиентов таймауты). Это отменяет для GUI и CLI решение Ф3 «поиск никогда не ждёт
обучения» (`docs/plans/2026-10-22-capabilities-phase3.md:81`, решение 11, и `:135`, «Готово, когда»).

Цель: первый поиск новой категории в GUI и CLI видит бренды, модели и состав из её обучения; пользователь видит, что
идёт платное обучение, и может искать без него или отменить.

## Что есть сейчас (2026-10-24, main `4ced2dd`, v0.8.0)

**Условие автообучения** (`src/buysmarter/services/auto_learn.py:66` `should_auto_learn`): `knowledge_missing` прогона,
`intent` ∈ {product, need}, разбор через LLM, имя ≤ 60 символов без мусора, `claude_available()`, лимит в час не
исчерпан (`_over_limit`, `:43`; `auto_learn_per_hour`, `config.py:67`, `BUYSMARTER_AUTO_LEARN_PER_HOUR=0` выключает),
у записи нет книг (`has_books`), нет отметки `learning_started_at` моложе 15 мин и `learn_failed_at` моложе 24 ч.
`count_start()` (`:94`) считает старт во входе, который решил. `auto_learn()` (`:120`) — отметка, `learn_category`,
снятие отметки; сбой → `learn_failed_at`, `False`. `CancelledError` не ловится: после отмены отметка «идёт» висит 15
минут. Докстринг модуля (`:4`): «The search never waits for the result».

**Где решается «новая»** (`services/recommend.py:382` `recommend`): разбор и уточнение (`understand_request`, `:273`),
профиль (`_resolve_knowledge`, `:224` → `capabilities/classify.py:102` `ensure_profile`: Jev при первом виде категории),
вопрос возможности (`ask_capability`, `:424`), затем источники (`pick_sources`, `:426`) и сбор. `knowledge_missing`
считается по разрешённому профилю (`:455`): нет книг ни в своей записи, ни у синонима, родителя или похожего профиля.
Значит, всё нужное для решения «ждать» известно на `:424`, до первого запроса к маркетплейсу. Образец паузы —
`NeedsClarification` (`services/understanding.py:82`): ядро поднимает исключение, вход спрашивает и зовёт снова;
телеметрия различает исход (`recommend.py:210`, `outcome = "clarify"`).

**GUI.** `gui/learning.py:23` `CategoryLearning` — задачи по категориям; `auto_start` (`:61`) проверяет условие,
`_decided` (`:77`) считает старт и запускает `auto_learn`; отмены по категории нет. Отчёт: `_after_shown`
(`gui/screens/report.py:374`) после отчёта зовёт `auto_start` (`:382`); `_knowledge_banner` (`:389`) — текст и кнопка
«Изучить категорию», статус с таймером (`_render_learning`, `:431`), по готовности — «Повторить поиск»
(`rerun_requested`). Поиск: `gui/screens/search.py:397` `_launch`, `_search` (`:436`) переводит `NeedsClarification` в
`AskUser` (`:446`), `_on_finished` (`:502`) разбирает исходы, «Отмена» (`:466`). Закрытие окна спрашивает про идущее
обучение (`gui/app.py:216`), повтор — `app.py:238`.

**CLI.** `cli/main.py:323` `recommend`, флаг `--learn` (`:353`, «Learn a new category after the report»).
`recommend_pipeline` (`:491`) крутит раунды уточнения (`:528`). После отчёта `_offer_learning` (`:412`, вызов `:400`):
на TTY «Изучить категорию сейчас (1–3 мин)? [y/N]», затем «Повторить поиск с новыми знаниями?» и `_rerun`.

**MCP и воркер** (`mcp_server/server.py:57`, `worker.py:128`, `:146`): обучение в фоне после отчёта; не меняются.

**Таймаут обучения:** `learn_category` с веб-поиском ограничен `_WEB_SEARCH_TIMEOUT = 600` с
(`knowledge/generate.py:216`); воркер дополнительно — `asyncio.wait_for` (`worker.py:136`).

**Документы:** карта `docs/logic-map.md` шаг 6 (`:169`), строка GUI в таблице входов (`:91`), побочный поток «Learning a

## Риски

- **Деньги без явного согласия в GUI.** Ожидание стартует платный `opus` без вопроса. Цена и длительность — в строке ожидания, «Отмена» сразу останавливает; лимит в час остаётся.
- **Отмена не убивает процесс `claude`.** Если `claude_cli` при отмене корутины не завершает подпроцесс, обучение дописывает книги после «Отмены». Проверить на шаге 1 (тест с медленным фейком и живой прогон шага 9); если не убивает — записать как известное ограничение, книги после отмены не вредны.
- **Ожидание до 10 минут** при зависшем веб-поиске (`_WEB_SEARCH_TIMEOUT = 600`). Отдельный таймаут ожидания не вводим: у пользователя есть «Искать без изучения»; таймер показывает, сколько прошло.
- **Повторный разбор в GUI** после обучения — лишний LLM-вызов (секунды). Принять; если заметно на живом прогоне — передавать `parsed`, как CLI.
- **Тесты GUI на ожидание** зависят от сигналов `CategoryLearning`; фейковое обучение с ручным `release` уже есть в `tests/gui/test_learning.py` — переиспользовать.
