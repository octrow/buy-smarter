# План: Ф4 — новые возможности уровня запроса

Фаза 4 по ADR-0005. Этот документ — про возможности, которые включает сам запрос: совместимость («зарядка для
Xiaomi 13»), размеры шин и матрасов, исключённые вещества («без сульфатов»), «только оригинал», «только б/у»; плюс
выключатели рынка б/у и перенос официальных магазинов на возможности. Идёт параллельно с Ф3 после слияния Ф2.

Цель: «чехол на iPhone 15», «шины 205/55 R16», «матрас 160х200», «шампунь без сульфатов», «Dyson только оригинал»,
«б/у ноутбук» дают осмысленную выдачу, а отказ всегда означает доказанное несовпадение.

Версия 2: переписан по независимому ревью (Opus, 2026-10-22). Главное: починка аксессуаров шире (маркер в самой
категории, основы, критерии Jev и LLM); fit через параметр `model_tokens` у `rank()` с границей строки, без нового
хука; каждая возможность убирает свою фразу из обязательных свойств и из текста для веществ; dims смотрит только
название и ключи размера; original_only без `reject_listing`, с путём «всё скрыто → OLX»; рынок б/у — только
выключатель, раздел остаётся в ядре; одежда и обувь в dims не дублируют size.

## Что есть сейчас (2026-10-22, до Ф1–Ф3)

**Аксессуары** (`llm/relevance.py:128-143`, маркеры `:73-81`). Проверено прогоном:

| Категория | Название | Сейчас |
|---|---|---|
| «чехол на iPhone 15» | «Чехол Spigen для iPhone 15» | отсечено (`чехол`) |
| «зарядка» | «Зарядное устройство Xiaomi 67W» | отсечено (`зарядн`) |
| «фильтр для воды» | «Фильтр Аквафор» | отсечено (`фильтр`) |
| «чехол» | «Чехлы для iPhone 15» | проходит случайно («чехол» ⊄ «чехлы») |
| «зарядка» | «Зарядка Baseus 20W» | проходит случайно (основа «зарядк», а не «зарядн»; комментарий `:82` неверен) |
| «робот пылесос» | «Аккумулятор для Dyson» | отсечено — верно |

Второй проход тоже режет: критерии Jev `_RELEVANCE_CRITERIA["false"]` (`relevance.py:59-67`) и запасной промпт LLM
(`:162-168`) прямо называют «charger, case, filter» нерелевантными. Частично спасает только порог `_restore_min`
(3 кандидата, `services/recommend.py:653-671`).

**Модель в запросе** (`ranking/model_tokens.py`): токен — латиница + цифра, компактная подстрока; множитель
`_MODEL_MISMATCH_FACTOR = 0.85` в `score()` (`ranking/engine.py:477,660-662`), токены из сырого `query` (`:736`).
«Xiaomi 13», «iPhone 15» токена не дают; «S24» даёт. Промпт разбора: «named model stays in category»
(`llm/prompts.py:63-66`).

**Свойства** — подстрока после «нижний регистр, без дефисов и пробелов» (`ranking/filters.py:26-47`), проверка только
при непустых характеристиках (`:127-131`): «205/55 R16» ≈ «205/55R16»; «160х200» (кириллица) ≠ «160x200». LLM кладёт
размеры, «без сульфатов», «оригинал» в `required_features`. Состав — в `COMPOSITION_SPEC_KEYS`
(`knowledge/ingredients.py:38`), текст — `composition_text`. Вещества для composition читаются из текста категории
(`recommend.py:235-238`; после Ф2 — из `search_phrase`).

**Подделки** — в ядре; закрытые для ролей (`ranking/selection.py:149-166`: имитация бренда `:159`, вердикт отзывов,
подозрительная цена) остаются в рейтинге. Все закрыты → `_pick_best` берёт верхний (`:295-297`). «Официальный
продавец» уже первым в плюсах (`engine.py:595`).

**Рынок б/у:** OLX включается выбором источников; у `recommend()` по умолчанию `["kaspi"]` (`:420`), GUI и API
передают выбор человека; раздел собирается асинхронно, с LLM (`canonicalize_used_titles`, `matching.py:700-727`), из
`deduped`, OLX-кандидатов и книг; путь `NoCandidatesPassed → NoNewPick` (`recommend.py:479-484`). Последний
OLX-коммит параллельной сессии — `7968b6b`. **Официальные магазины:** `official_candidates`
(`official_stores.py:238-258`), предикат аудитории до среза `_PER_STORE`.

**После Ф1–Ф3:** контракт возможностей (хуки `query`, `searches`, `relevance`, `reject_listing`, `hard_features`,
`enrich`, `reject_content`, `prepare`+`axis`, `notes`, `section`, `clarify`); `ranking/` не импортирует `capabilities/`;
size и audience — возможности; разбор с `product_type`, `search_phrase`, `condition`; ответ на уточнение — `answer`
(Ф2, решение 6); атрибуты `jev_question`, `title`, `level`; у counterfeit/official/used `jev_question=None` (Ф3,
решение 6). Сигнатуры хуков сверить после шага 6 Ф1.

## Решения

| # | Вопрос | Решение | Почему |
|---|---|---|---|
| 1 | Аксессуары (ядро) | В `accessory_reason`: маркер, который встречается в начале слова **в самой строке категории**, не аксессуар (`_marker_at_word_start(m, category.lower())`). Основы: `зарядн` → `заряд`, добавить `чехл`. В критерии Jev и запасной промпт LLM — «unless `category` itself is that kind of item». Отдельным коммитом в начале фазы. | Чинит «чехол», «чехлы», «зарядка», «фильтр для воды» и без совместимости. |
| 2 | Новые поля разбора | `fit_target: str \| None`, `dims: dict[str, str]` (только `tyre`, `mattress`), `exclude_substances: list[str]`, `original_only: bool`; все со значениями по умолчанию, в публичной `ParsedRequest` тоже. Промпт: «X для/на Y» → `product_type=X`, `fit_target=Y`, модель Y не в категории; антипример — «смартфон iPhone 15» (модель — сам товар). Размеры, «без X», «оригинал» — не в `required_features`. | Возможности уровня запроса включаются полями разбора. |
| 3 | Разбор без LLM | `fit_target`: «для\|на <цель>», где первое слово цели не число и не единица (gb, tb, mah, w, l, mm, e27…), а цель — латиница с цифрой или статический список брендов устройств (iphone, айфон, samsung, xiaomi, redmi, poco, huawei, honor, ps5, playstation, macbook…). Шина: `(?<!\d)\d{3}/\d{2}\s*/?\s*Z?R\s*\d{2}C?(?!\d)` (с кириллической «Р»). Матрас: `(?<!\d)\d{2,3}\s*(?:[xх×*]\|на\|/)\s*\d{3}(?!\d)`, стороны сортируются. «без <слово>». «только оригинал\|\bоригинал\b» (не «оригинальный»). | Без ложных «на 64 GB», «крем для лица», «на зиму», «1600x2000». |
| 4 | fit | Возможность уровня запроса. `query`: `search_phrase + " " + fit_target`. Штраф — **без нового хука**: `recommend()` передаёт в `rank(..., model_tokens=…)` компактную строку `fit_target`, если он задан, иначе `extract_model_tokens(query)` — один штраф, без двойного «S24». Совпадение — целой строкой с границей `(?!\w)` справа (разрешены перечисления «15/15 Pro»): «iphone15» не совпадает с «iphone15pro». Если в пуле ноль совпадений — штраф не ставится (решает `prepare`). `notes`: плюс «подходит к Y». | Контракт Ф1 не меняется; «чехол на iPhone 15» не хвалит чехлы для Pro. |
| 5 | dims | Только шины и матрасы (одежда и обувь — size из Ф1). `query` добавляет нормализованный размер в поиск. Нормализация: «х», «×», «*», «на», «/» → «x», стороны матраса по возрастанию; «R 16», «Р16», «ZR16», «R16C» → «R16». Сравнение — по названию и **только** ключам размера (для шин у Kaspi — ширина, профиль, диаметр; для матраса — «Размер», «Ширина», «Длина»), не по всем характеристикам. Отказ, если указан размер того же вида и ни один не равен запросу: по названию — `reject_listing` (работает и на OLX, и на официальных магазинах), по ключам — `reject_content`. Не указан — минус «размер не проверен». `hard_features` убирает размер из обязательных. `clarify`: шины или матрас без размера — вопрос (матрас — варианты 90×200, 140×200, 160×200, 180×200); ответ на этот вопрос разбирается в `dims`, а не в `product_type` (правка к Ф2 решению 6 для `kind=capability`). Какие типы требуют размер — по основе слова (шин, резин, покрыш, автошин; матрас), не по равенству `product_type`. | «Размер упаковки 50x50x160» и «1600x2000» не дают ложного отказа. |
| 6 | exclude_substances | Без LLM. Иглы конкретные: сульфаты → SLS, SLES, sodium lauryl sulfate, sodium laureth sulfate, лаурилсульфат, лауретсульфат (не голое «сульфат»: «магния сульфат» в витаминах); парабены → paraben, methylparaben, propylparaben, …парабен; сахар → сахар, сахароза, sucrose (не «сахарозаменитель»); лактоза → лактоза, lactose (не «безлактозный»). Игла после «без\|free\|не содерж» пропускается. `reject_content`: игла в `composition_text` → «содержит <X>»; состава нет → минус «состав не проверен на <X>»; «без X» в названии → плюс. `query` убирает «без X» из текста, по которому composition ищет вещества; в `search_phrase` для площадок остаётся, но фильтр релевантности получает фразу без «без X» (иначе критерий «has every property» станет жёстким). `hard_features` убирает «без X». | «шампунь без сульфатов» не делает сульфат требуемым веществом. |
| 7 | original_only | Без `reject_listing` (имитация бренда — поле кандидата, и она уже закрывает роли, `selection.py:159`). Атрибут `drops_barred = True`: после прохода по отзывам ядро убирает закрытых для ролей из рейтинга, прибавляет их к `rejected_count` и `rejected_reasons["подозрение на подделку"]`, пишет «Скрыто N подозрительных предложений» (с раскрытием списка в GUI и markdown; поле в `RecommendOutcome`). Все закрыты → `NoCandidatesPassed({"подозрение на подделку": N})` → путь `NoNewPick` с OLX. `hard_features` убирает «оригинал». | Без `IndexError` в `_pick_best` и с честными счётчиками. |
| 8 | used_only | `condition == "used"` (Ф2) включает возможность уровня запроса: `sources` добавляет OLX **до** `resolve_sources` (`unavailable_sources` — по новому списку); раздел б/у идёт первым; строка Ф2 «Вы искали б/у» заменяется, не дублируется. Один код для CLI и MCP (`cli/report.render_markdown`). | Решение 5 штурма. |
| 9 | Рынок б/у | Категорийная возможность-**выключатель**: `sources` только **убирает** OLX, если возможность выключена (обучение Ф3 или пользователь). Добавляет OLX только used_only. Сбор, фильтр и оба раздела (с рекомендацией и путь `NoNewPick`) остаются в ядре. `jev_question=None` (согласовано с Ф3 решением 6): «гречка без б/у» выключается обучением, не Jev. | Не меняет выбор человека и характеризационные тесты; перенос раздела — после v1. |
| 10 | Официальные магазины | Категорийная возможность, включена по умолчанию; хук `candidates` вызывает `official_candidates` с **общим** предикатом всех `reject_listing` (аудитория, dims по названию), а не только аудитории — до среза `_PER_STORE`. | Новые запросные отказы работают и в магазинах. |
| 11 | Новые хуки | `sources(ctx, selected) -> selected` и `candidates(ctx) -> list[Candidate]` (async), атрибуты `drops_barred`, `requires_dims`; новые возможности объявляют `title` и `level` из Ф3. Первым коммитом фазы, сразу в main (после шага 1 Ф3). | Ф3 правит тот же контракт. |

## Порядок работы

Тест первым, коммит на шаг; весь набор и характеризационные тесты Ф1 зелёные после каждого, ожидаемые значения не
меняются (новые возможности включаются только новыми полями разбора; шаг 1 меняет только категории, где маркер
совпадает с самой категорией — в характеризационных сценариях таких нет, проверить).

1. **Аксессуары.** Тесты: «Чехол Spigen для iPhone 15», «Чехлы для …», «Зарядное устройство …», «Зарядка Baseus», «Фильтр Аквафор» для своих категорий — не отсекаются; «Аккумулятор для Dyson», «Фильтр HEPA для …» для «робот пылесос» — отсекаются; критерии Jev и промпт LLM — тест текста; живая проверка «чехол на iPhone 15» с LLM.
2. **Хуки и атрибуты** — сразу в main.
3. **Поля разбора + fit** (одним слиянием: без fit промпт вынет модель из поиска). Разбор: «зарядка для xiaomi 13», «на айфон 15», «стекло на S24»; антипримеры: «крем для лица», «кроссовки на зиму», «для детей», «флешка на 64 GB», «повербанк на 20000 mAh», «смартфон iPhone 15». fit: «iPhone 15» против «iPhone 15 Pro» и «iPhone 15/15 Pro»; один штраф для «стекло на S24»; ноль совпадений в пуле — без штрафа.
4. **dims.** Нормализация шин и матрасов; «1600x2000» и «Размер упаковки 50x50x160» — без отказа; другой размер в названии — отказ на OLX и в официальном магазине; уточнение и ответ в `dims`; «зимние шины», «автошины», «резина» требуют размер.
5. **exclude_substances.** Иглы и отрицания: «sulfate-free», «без добавления сахара», «магния сульфат», «безлактозный»; «шампунь без сульфатов» при включённой composition — сульфат не требуемое вещество, `NoSubstanceMatch` нет.
6. **original_only.** Скрытые прибавлены к счётчикам; все закрыты → `NoNewPick`; «оригинальный подарок» не включает возможность.
7. **used_only.** OLX добавлен до `resolve_sources`; раздел первым в CLI, GUI, MCP; строка Ф2 заменена.
8. **Рынок б/у — выключатель** (после `git log -- services/matching.py services/recommend.py` с `7968b6b`). Характеризационные сценарии с OLX и `NoNewPick` зелёные.
9. **Официальные магазины → возможность**, общий предикат. Характеризационный сценарий с магазином зелёный.
10. **Документы.**
11. **Живой прогон:** «чехол на iPhone 15», «зарядка для Xiaomi 13», «стекло на S24», «шины 205/55 R16 зимние», «зимние шины» (уточнение → ответ «205/55 R16»), «матрас 160х200», «шампунь без сульфатов», «пылесос Dyson только оригинал», «б/у ноутбук для учёбы».

## Вне этого шага

- Перенос раздела б/у (`section`) в возможность; ранжирование б/у как основного пула.
- Размеры одежды и обуви как жёсткий фильтр; кольца, диагональ, рама велосипеда.
- Год и двигатель авто («масло для Kia Rio 2018» — год в названиях не пишут, совпадение не найдётся; штраф снимается правилом «ноль совпадений в пуле»).
- Модель самого товара в «картридж HP 123 оригинал» (это не fit; оставляем модельным токенам).
- Цена за единицу, сертификаты, страна, срок доставки, «вид животного», сравнение «A или B», наборы.
- Перенос всей логики подделок в возможность counterfeit.

## Риски

- **Параллельная Ф3 правит `capabilities/base.py`, `knowledge/profile.py`, `services/recommend.py`.** Шаг 1 Ф3 и шаг 2 Ф4 — в main первыми, остальное потом; правки `recommend()` локальные.
- **Шаг 1 меняет отсев для существующих категорий-аксессуаров.** Это намеренно; характеризационные сценарии такие категории не используют — проверить перед коммитом.
- **Список брендов устройств для fit без LLM неполон.** Последствие — `fit_target` не найден и поиск идёт по категории, как сейчас; дополнять по логам.
- **Словарь исключённых веществ неполон.** Пропуск даёт отсутствие отказа, а не ложный отказ; минус «состав не проверен» честен.
- **`drops_barred` прячет настоящий товар с ложным подозрением.** Список скрытых раскрывается в отчёте.
