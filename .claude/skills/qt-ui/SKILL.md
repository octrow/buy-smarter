# Qt UI: как соседи, через токены, проверка снимками

Приложение — «lab report» (`DESIGN.md`): спокойные нейтральные, белые карточки
протокола, один teal-акцент, вердикты семантическими цветами. Хороший результат —
экран, который нельзя отличить от соседних, а не «красивый». Пользователь сам
выбрал собственную тему на токенах и qtawesome вместо готовых библиотек, так что
чужие темы (Fluent, qt-material, «Modern Enterprise») не подтягивать.

Порядок источников, когда они расходятся:
**замечание пользователя → соседний экран → `DESIGN.md` → `theme/__init__.py` →
`~/dev/docs/GUI/qt-desktop-guide.md` → этот скилл → вкус.** Если замечание спорит с
`DESIGN.md` или соседом — назвать конфликт одной строкой и спросить.

**Голый `/qt-ui` без задачи** — не новый полный аудит, а список «Открытые мелочи»
ниже: снять ДО, взять пункты по порядку, исправленное из списка вычеркнуть в том же
коммите. Список пуст — тогда аудит по чек-листу.

### Открытые мелочи

- «Стиль»: миниатюры образцов разной ширины.
- «Категории»: колонка «Родитель» пустая у всех строк.
- «Прошлые поиски»: длинные запросы в списке урезаны многоточием.
- «Поиск»: карточка на 3px выше в одной из тем.
- «Настройки поиска», «Стиль»: подписи `QFormLayout` на пару px выше центра поля.

### Сознательно не трогаем (не находить заново)

- Стрелка сортировки у края колонки — её так рисует Qt.
- Кнопки «Стиля» в два ряда — сгруппированы по смыслу.
- «Недавние поиски» на «Поиске» — заголовок вне карточки: иначе рамка в рамке.
- Статус рядом с кнопками без ограничения ширины — иначе растягивает кнопки.

## Шаг 0. Снимок ДО (всегда первым)

```bash
QT_QPA_PLATFORM=offscreen uv run --extra gui --extra style python scripts/screenshots.py <scratchpad>/before
```

GUI — опциональный extra: без `--extra gui --extra style` (как в `ci.yml`) скрипт,
pytest и shotdiff падают с `ModuleNotFoundError: PySide6`, особенно в свежем
worktree. Получается `before/{light,dark}/`: каждый экран в 1280×800, в
минимальном окне (`*-960x640.png`; самые частые поломки — сжатые колонки, обрезанный
текст — видны именно там) и на весь экран пользователя (`*-2560x1440.png`; там видно
растянутые по высоте карточки и строки шире 1200px), отчёт, заполненный фикстурой `make_result()`, во всю
длину (`report-full*.png`; `02-Отчёт` тоже заполнен), плюс `clarify`, `learning`,
`category`. Это офскрин на временном хранилище: файлы пользователя не трогает.

Помнить:
- Пустой «Отчёт» скрипт не снимает: правишь пустое состояние — сними его сам.
- Имена в `docs/screenshots/desktop/` не совпадают с выводом скрипта — см. «Эталоны»
  в конце.

Смотреть PNG самому (Read), каждый экран в обеих темах. Если пользователь назвал
проблемы — начать с них. Если сказал «найди сам», пройти по чек-листу дефектов
ниже и выдать **список до правок**: экран · тема · что не так · какое правило
нарушено. Потом править.

## Шаг 2. Правило по умолчанию для каждой мелочи

Это «как уже сделано в коде». Если сосед делает иначе — прав сосед.

- **Цвет и размер — только из токенов.** Литерал `#…`, `setStyleSheet("color: …")`
  в экране, `QColor(…)` с числами, пиксели мимо `TYPE`/`SPACE` — дефект. Новый
  стиль — правило в `build_qss` по object name или dynamic property (`primary`,
  `state`), а не inline-стиль в виджете. Новый цвет — парой в `LIGHT` и `DARK` и,
  если это текст на фоне, строкой в `TEXT_PAIRS` (её проверяет контраст-тест).
- **Типографика:** 12 caption · 14 body · 16 заголовок карточки · 20 название
  товара · 24 балл и цена · 28 заголовок экрана (один на экран, 28/700).
  Один шрифт, Inter.
- **Отступы:** сетка 4px (4, 8, 12, 16, 24, 32). У layout'а карточки нулевые поля —
  рамку даёт padding из QSS (`card_body`). Близость = смысл: строка < группа <
  карточки < край экрана.
- **Отступы — только токенами ритма:** между карточками `PAGE_GAP` (24, не меньше
  отступа внутри карточки), между строками внутри карточки `CARD_GAP` (12, его ставит
  `card_body`). Без явного `setSpacing` Qt ставит свои 6px, мимо сетки.
- **Абзац текста** — `theme.Prose`: переносится и не шире 560px (~70 знаков). Обычный
  `QLabel` с `setMaximumWidth` не годится: Qt считает его высоту для полной ширины и
  обрезает вторую строку. Статус рядом с кнопками — простой `QLabel`, иначе
  освободившееся место растянет кнопки.
- **Контролы:** любое поле 36px высотой. Подписи: в форме «Поиска» — 12px над полем;
  на экранах-настройках («Настройки поиска», «Стиль») — слева в `QFormLayout`. Так
  сложилось, держаться того, что на экране; менять схему — только по решению
  пользователя. Начала полей выровнены по одной вертикали.
- **Кнопки:** одна primary на экран (`primary="true"`), остальные secondary;
  flat-акцент только для действий в строке («Повторить»).
- **Статусы:** label с `theme.set_state(widget, "state", …)`: done/ok, running,
  failed/missing, skipped/waiting, warning. Не красить руками.
- **Таблицы:** показывают все строки (`gui/tables.py`), прокручивается страница, а
  не таблица; без вертикальной сетки; заголовки 12/600, приглушённые, слева.
- **Иконки:** `mdi6.*` через `theme.icon`, приглушённые по умолчанию, акцентные у
  выбранного; эмодзи в хроме нет.
- **Ширина:** контент не шире `CONTENT_MAX_WIDTH`; всё обязано помещаться в
  минимальное окно 960×640 — и по ширине, и по высоте; на весь экран (2560×1440) карточки
  не растягиваются по высоте (лишнее место — пустым `addStretch` в конце страницы). Экран, который не влезает,
  прокручивается (`_scrolled` в `app.py`), а не сжимает строки. Растягиваемая колонка
  таблицы (`stretch_column`) не уже `TEXT_FLOOR_PX`, дальше таблица едет вбок.
- **Пустое состояние** — та же страница, что у экрана с данными: заголовок 28/700
  слева сверху и одна приглушённая строка под ним, не текст по центру пустоты.
- **Язык:** весь текст в хроме — русский; английский остаётся только в формулировках
  отчёта, общих с CLI.
- **Тема** следует за ОС и меняется на лету: цвет, который читают один раз при
  создании виджета (иконка, `QPalette`), должен обновляться при смене схемы — см.
  `bind_icon`.
- **Тексты:** в `labels.py`; формулировки отчёта — как в CLI («Best pick», «Score»,
  «Отсеяно»). Поведение CLI и GUI одинаковое: правка смысла на экране — повод
  проверить CLI.

### Чек-лист дефектов (что искать на снимках)

Обрезанный или многоточием урезанный текст · подпись, перенесённая без нужды ·
поля разной высоты или не на одной вертикали · отступы не по сетке и неровный ритм
между карточками · белое на белом / серое на сером в одной из тем · иконка, которая
не поменяла цвет вместе с темой · две primary-кнопки · горизонтальная прокрутка или
вылезший за край элемент в 960×640 · таблица со своей прокруткой · заголовок
экрана не 28/700 · пустое состояние без текста · расхождение с тем же элементом на
соседнем экране · колонка таблицы, сжатая до букв в столбик · текст ячеек не на одной
вертикали с заголовком колонки · прокрутка внутри прокрутки · пустая карточка с одним
заголовком · `QTextBrowser` с горизонтальной полосой.

### Законы UX и правила сетки → что они значат здесь

Полный перевод под Qt — `references/ux-rules.md` в плагине
`~/dev/octrow-skills/plugins/qt-ui/skills/qt-ui/`. Для этого приложения:

| Правило | Здесь |
|---|---|
| Jakob, Similarity | Как соседний экран; нативные `QFileDialog`/`QMessageBox`, Enter = «Найти», Esc закрывает диалог |
| Hick, Von Restorff | Одна primary на экран, акцент только на действии, выборе и балле |
| Doherty | Поиск идёт минуты: прогресс по этапам только вперёд и рабочая «Отмена» |
| Proximity, Common region, Miller | Группы — карточкой, не линиями; ≤7 полей в карточке |
| Paradox of the active user | Пустое состояние говорит, что делать дальше («Начните с экрана «Поиск»») |
| Peak-end | Отчёт — пик: карточка лучшего выбора — главный якорь экрана |
| Длина строки 40–70 знаков | Абзац — `theme.Prose` (560px) |
| Internal ≤ external | Внутри карточки 24px, между карточками `PAGE_GAP` = 24 |
| Никаких искусственных начертаний | Полужирный — статические Inter 400/600/700. Курсива в бандле нет: в markdown «Прошлых поисков» курсив синтетический |
| Нет ложного дна | Карточка, обрезанная ровно по низу окна, прячет прокрутку: смотреть 1280×800 и 960×640 |

Из веб-правил здесь не берём: тело 16px (у нас 14 по `DESIGN.md`), пары шрифтов,
адаптивные 12-колоночные сетки и брейкпоинты (у окна один минимум — 960×640),
пустоты 48–96px между секциями, Z-паттерн и hero.

Отдельно — **работают ли токены на самом деле**, а не только написаны ли они в коде.
Увеличить кроп заголовка карточки и обычного текста рядом: если 600 выглядит как 400,
вес шрифта не применяется (вариативный Inter Qt может видеть одним стилем Regular).
Такой дефект бьёт по всем экранам сразу и в коде экранов не виден.

### Ловушки Qt (каждая уже стоила круга)

| Симптом | Причина → что делать |
|---|---|
| Правило для `QPushButton` не действует на кнопки в карточке | `QGroupBox QWidget` специфичнее → писать `QGroupBox QPushButton` |
| Текст в spinbox прилип к краю | padding из QSS не доходит до текста → `box.lineEdit().setTextMargins(...)`, как `prefs_fields.py` |
| Колонка таблицы сжалась до букв в столбик | Stretch рядом с ResizeToContents → `tables.stretch_column` (пол `TEXT_FLOOR_PX`) |
| `resizeSection` не держится | заголовок перезаписывает его в своём проходе → `QTimer.singleShot(0, ...)` |
| Перенесённый `QLabel` с max-width обрезает строку | высота считается для полной ширины → `theme.Prose` |
| Отступы «почти по сетке» | Qt ставит spacing 6px и поля 9–11px сам → всегда явный `setSpacing`/`setContentsMargins` |
| В markdown `_x_` подчёркнут | Qt рендерит его как underline → глушить в документе (`saved._mute_notes`) |
| Полужирный выглядит обычным | вариативный шрифт = один Regular → статические файлы весов |
| `QTextBrowser` ездит вбок на 1px | переполнение на округлении → `ScrollBarAlwaysOff` по горизонтали + перенос по словам |

## Шаг 3. Проверить до доклада

1. **Снимок ПОСЛЕ** в `<scratchpad>/after` той же командой.
2. **Дифф снимков**, чтобы поймать побочный эффект общей правки QSS на чужих экранах:
   ```bash
   uv run --extra gui python <папка этого SKILL.md>/shotdiff.py <scratchpad>/before <scratchpad>/after
   ```
   Путь к скрипту брать абсолютным, от этого SKILL.md: в worktree папки скилла может
   не быть. Печатает изменившиеся снимки с долей изменённых пикселей; код выхода 1
   значит «есть отличия», для ожидаемой правки это норма. Изменилось то, что не
   должно было, — разобраться до доклада.
3. **Посмотреть ПОСЛЕ самому** (Read), рядом с ДО и с соседом: тот же кегль, та же
   высота контролов, тот же отступ, обе темы.
4. **Тесты** (только затронутые):
   ```bash
   uv run --extra gui --extra style pytest -q tests/gui/test_theme.py tests/gui/test_<экран>.py
   ```
   Правка `app.py` или `theme` — добавить `tests/gui/test_app.py`. Правка в
   `services/` (например, поле `doctor.Check`) — добавить `tests/cli`: CLI читает то же.
   Не пропускать вывод через `| tail`: пайп съедает код выхода pytest, и падение
   выглядит как успех.
5. `uv run ruff check src/buysmarter/gui && uv run ruff format --check src/buysmarter/gui`.

Тест не проходит — сказать об этом и показать вывод, а не выдавать снимок за
проверку.

## Коммит

В репо параллельно коммитят другие сессии, индекс общий: файлы, оставленные в
индексе, уезжают в чужой коммит. Поэтому:

```bash
git status --short          # чужие изменения не трогать и не стейджить
git commit -m "fix: ..." -- <только мои пути>
git show --stat HEAD        # в коммите только мои файлы — потом push в main
```

Уехало в чужой коммит — сказать пользователю, историю не переписывать.
